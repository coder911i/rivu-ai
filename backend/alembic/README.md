# Rivu database migrations

Production schema changes must use Alembic. The API refuses to start in production when AUTO_CREATE_SCHEMA=true.

From backend:

    alembic revision --autogenerate -m "initial schema"
    alembic upgrade head

Review autogenerated migrations before deployment. Never use SQLAlchemy create_all as the production migration mechanism.

Production settings:

    APP_ENV=production
    DEBUG=false
    AUTO_CREATE_SCHEMA=false

The Alembic environment imports Rivu's SQLAlchemy metadata and reads DATABASE_URL from the environment.
